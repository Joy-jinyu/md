| External images (user decision on 2026-11-25). Display them directly. The site stores no private data. In nsh 0.6.0 images and fetch share `capabilities.network`, which has no image-only control. Use `network.http: [{ host: "*", methods: ["GET"] }]` in `nsh.json` and avoid `hosts: ["*"]`. **Web.** The rule makes nsh's generated `connect-src` allow all domains. The deployed site adds a `connect-src` response header listing only allowed hosts. The browser enforces both policies, and `<img>` loads fall outside `connect-src`. Include `Referrer-Policy: no-referrer`, `X-Content-Type-Options: nosniff`, and `object-src 'none'; base-uri 'self'; frame-ancestors 'none'`. Cloudflare Workers static assets reads these headers from the packaged `_headers` file. At the end of `make build-web`, `scripts/web-headers.mjs` generates it from `network.hosts` (HTTPS only) and `web.connect` (WS only) in `nsh.json`. Keep hostnames centralized there. **Local development with `make dev-web`.** The dev server sends none of these headers. Its page has no CSP and can connect to any host. The protection applies on the deployed site and servers configured to send `_headers`. **macOS.** There is no CSP layer. The same rule lets app JavaScript send GET requests to any host. This is a known trade-off. The app includes no third-party scripts outside the isolated Mermaid WebView. Opening a document on either platform sends requests to image hosts, which can see the IP and time. The web app omits Referer, but the browser still sends eligible third-party cookies (SameSite=None when third-party cookies are allowed), as verified in headless Chrome on 2026-11-25. The CSP cannot govern those cookies. | L0 | Review `nsh.json`. Inspect `dist/web/Pairdown/_headers` after `make build-web`. Check production response headers with `curl -sI https://markdown.pairwise.site/`. |
